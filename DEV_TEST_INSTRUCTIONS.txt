DEV ONLY — V3.2.1 Network Handoff Fix

สิ่งที่แก้:
- อัปเดต Firebase Web SDK จาก 10.12.0 เป็น 12.16.0
- ตรวจจับการเปลี่ยนชนิดเครือข่าย (Wi‑Fi/มือถือ) แม้ browser ไม่ยิง offline/online
- เมื่อ Firebase REST เข้าได้แต่ realtime ค้าง จะ restart เฉพาะ RTDB transport ก่อน
- ถ้ายังไม่กลับ จึง reload หนึ่งครั้งพร้อมล้างเฉพาะ Cache Storage ชื่อของ SKE
- ไม่ลบ localStorage, ข้อมูลล็อกอิน, outbox หรืองานค้างของผู้ใช้
- Service Worker ไม่ดัก fetch และไม่ cache หน้า HTML/Firebase/API อีก
- worker ชื่อเดิม firebase-messaging-sw.js เป็นตัวส่งต่อไป worker ใหม่ รองรับเครื่องเก่า

วิธีอัปโหลดทดสอบ:
1. อัปโหลด index.html, sw.js, firebase-messaging-sw.js และ manifest.json พร้อมกัน
2. รอระบบโฮสต์ deploy สำเร็จ
3. เปิดเว็บ/แอปตามปกติ ไม่ต้องลบข้อมูลเว็บไซต์
4. ตรวจเลขเวอร์ชันให้เป็น v2026.07.26-dev-v3.2.1-network-fix
5. ทดสอบ Wi‑Fi → 4G/5G → Wi‑Fi อย่างน้อย 5 รอบ
6. แต่ละรอบให้รอไม่เกินประมาณ 20–25 วินาที ระบบควรกลับมาเอง
7. ทดสอบ Airplane Mode และ background/resume เพิ่มอีกอย่างละ 3 รอบ
8. ทดลองบันทึกสถานะจริงหลัง reconnect เพื่อยืนยันว่าซิงค์สำเร็จ

ถ้าแถบแดงยังค้าง:
- แตะแถบแดงหนึ่งครั้ง ระบบจะ restart transport และ reload เป็นทางเลือกสุดท้าย
- ผู้ดูแลแตะเลขเวอร์ชัน 5 ครั้งเพื่อเปิด Debug Log แล้วคัดลอกส่งให้ผู้พัฒนา
- ไม่ต้องลบข้อมูลเว็บไซต์ เพราะจะทำให้ข้อมูลค้างในเครื่องและข้อมูลเข้าสู่ระบบหาย
